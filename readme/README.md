# 眼科 OCT 智慧管理平台（演示系统）· 交付说明 README

> 本文档面向甲方/答辩评审：说明环境依赖与一键安装、部署运行步骤、所用开源组件，以及码道（CodeArts）在本项目开发中的应用总结。
> 项目性质：**答辩演示系统**——以真实交互 + 集中管理的模拟数据呈现完整业务闭环，不对接真实 OCT 硬件、不运行真实 AI 模型。

## 一、项目简介与交付物

| 项 | 内容 |
|----|------|
| 项目名称 | 眼科 OCT（光学相干断层成像）智慧管理平台（演示系统） |
| 技术栈 | 前端 Vue 3 + Element Plus + Vite + ECharts；后端 Node.js + Express；数据层 JSON 文件库（`shared/db.json` 单一数据源） |
| 功能模块 | 数据中心大屏、患者管理、检查管理、AI 辅助诊断、设备管理、耗材管理、系统设置（7 个菜单）+ 移动端免登录页（2 页） |
| 代码规模 | 前端页面 14 个 / 组件 9 个；共享纯函数模块 9 个；后端 REST 接口 25 个；测试 23 个文件 / 183 条用例 |
| 交付物 | `backend/` `frontend/` `shared/` `docs/` 四目录 + 7 个验收脚本 + 本 README + 一键安装脚本 |

**演示数据（标准初始态）**：40 名患者 / 155 条检查记录 / 17 条检查预约 / 8 台 OCT 设备 / 14 种耗材 / 4 个演示账号；AI 报告与出入库流水按需产生。

## 二、环境依赖说明与一键安装

### 2.1 环境要求

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | **≥ 20.19**（推荐 22/24 LTS） | 前后端运行时；Vite 7 最低要求 Node 20.19 |
| npm | ≥ 10（随 Node 安装） | 依赖管理与脚本运行 |
| 操作系统 | Windows 10 / 11 | 验收脚本为 Windows 批处理（.bat）；源码跨平台可用 |
| 浏览器 | Chrome / Edge 等现代浏览器 | 界面依赖 Vue 3，不支持 IE |
| 数据库 / 容器 / 消息队列 | **无需** | 数据层为 JSON 文件库，零外部服务依赖 |
| 网络 | **无需外网** | 交付包已内置前后端依赖，可完全离线运行 |

### 2.2 一键安装（推荐）

双击运行根目录下的：

```
安装依赖.bat
```

脚本会自动完成：Node 环境检测 → 安装后端依赖（Express/CORS）→ 安装前端依赖（Vue3/Element Plus/ECharts 等）→ 打印启动指引。已内置依赖（`node_modules` 存在）时自动跳过，可重复执行。

> 脚本使用国内镜像（`registry.npmmirror.com`）加速，并显式指定缓存目录以避免部分机器系统 npm 缓存目录无写权限的问题。

### 2.3 手动安装（等效命令）

```bat
cd backend
npm install
cd ..\frontend
npm install
```

## 三、部署运行步骤说明

### 3.1 方式一：双击验收脚本（推荐，答辩现场使用）

根目录提供 7 个模块级验收入口，每个脚本会自动完成：**清理残留端口进程 → 检测/安装依赖 → 启动后端(3001) → 启动前端(5173) → 就绪探测 → 打开浏览器 → 打印验收步骤清单**。

| 验收脚本 | 对应模块 |
|----------|----------|
| `验收-01-登录与大屏.bat` | 登录页、RBAC 权限、主布局、数据中心大屏（5 类可视化） |
| `验收-02-患者管理.bat` | 患者档案列表、组合筛选、患者详情时间线（结论随日期演化） |
| `验收-03-检查管理.bat` | 检查预约、冲突拦截、模拟数据采集（SD/SS-OCT 双平台）、记录闭环 |
| `验收-04-AI辅助诊断.bat` | 3 秒读片动画、结构化报告（SVG 病灶圈注）、医生复核签发 |
| `验收-05-设备与耗材.bat` | 设备台账/详情趋势/状态切换联动、耗材库存告警与出入库 |
| `验收-06-移动端H5.bat` | 扫码入口（二维码）、移动端报告页与健康趋势页（免登录只读） |
| `验收-07-系统设置.bat` | 系统信息、账号权限矩阵、演示数据一键复位、关于 |

### 3.2 方式二：手动启动

```bat
:: 终端 1：启动后端（端口 3001）
cd backend
node server.js

:: 终端 2：启动前端开发服务（端口 5173）
cd frontend
npm run dev

:: 浏览器访问
http://localhost:5173/login
```

**演示账号**（密码统一为 `123456`）：

| 角色 | 账号 | 可见菜单 |
|------|------|----------|
| 管理员 | admin | 全部 7 个菜单 |
| 眼科医生 | doctor | 大屏、患者、检查、AI 辅助诊断 |
| 眼科护士 | nurse | 大屏、患者、检查 |
| 设备技师 | tech | 大屏、设备、耗材 |

### 3.3 移动端页面访问（免登录）

- 桌面端进入「AI 辅助诊断」读片后，点「手机扫码查看」，可扫码或用浏览器 **F12 → 设备模式（Ctrl+Shift+M）** 打开二维码中的地址；
- 移动端地址形式：`http://localhost:5173/m/report/{examId}`、`/m/patient/{id}`；
- 手机扫码需与本机处于同一局域网。

### 3.4 数据复位（每组演示前建议执行）

三种方式任选：

1. **界面方式（推荐）**：登录后进入「系统设置 → 数据维护」，按范围一键复位（患者与检查记录 / 设备与耗材 / 检查预约 / 全部演示数据），含二次确认；
2. **脚本方式**：`node shared\generate-patients.mjs`、`node shared\generate-assets.mjs`、`node shared\generate-reservations.mjs`；
3. **全部复位**：上述三个脚本依次执行，并清空 `shared/db.json` 中的 `reports` 与 `stockLogs` 字段。

### 3.5 测试与构建

```bat
cd frontend
npm run test     :: 运行 183 条组件/纯函数测试（vitest + jsdom）
npm run build    :: 生产构建
```

### 3.6 常见问题排查

| 现象 | 处理 |
|------|------|
| 端口被占用（3001/5173） | 验收脚本已内置残留进程清理；手动时可用 `netstat -ano \| findstr :3001` 查 PID 后结束 |
| 页面顶部出现红色「诊断」横幅 | 全局错误捕获提示，请将横幅文字反馈给开发方 |
| 大屏显示「数据加载异常」/ 列表为空 | 检查后端窗口是否正常（后端未启动时前端自动回退只读 Mock，写操作不可用） |
| 写操作（新建预约、报告签发、出入库）失败 | 需后端在线；Mock 只读模式下会明确提示 |
| 手机扫码打不开 | 手机需与本机同一网络；也可用浏览器设备模式模拟 |
| npm install 报缓存目录权限错误 | 使用 `安装依赖.bat`（已显式指定用户目录缓存） |

## 四、额外使用的开源组件说明

除 Vue 3 与 Express 主框架外，本项目引入的第三方组件如下（均为社区主流、许可证宽松）：

| 组件 | 版本 | 许可证 | 用途 |

### 4.3 后端依赖

| 组件 | 版本 | 许可证 | 用途 |
|------|------|--------|------|

| CORS | ^2.8.5 | MIT | 跨域支持（开发态前后端分端口） |

### 4.4 选型说明

- **未引入重型中间件**：无数据库（MySQL/Redis）、无对象存储（MinIO）、无容器（Docker）、无消息队列（RabbitMQ）——演示系统以轻量、免安装、可离线为第一优先；
- **数据层自研**：JSON 文件库 + 前后端共用的纯函数模块（过滤/分页/演化/流转/报告/系统信息），保证前后端数据天然同构；
- **二维码真实可扫**：选用 `qrcode` 而非在线二维码服务，避免外网依赖与地址外发。

## 五、码道（CodeArts）在项目开发中的应用总结

本项目**从零到交付全程由华为云码道（CodeArts）代码智能体协助完成**，应用方式与成效如下。

### 5.1 需求理解与项目定位（开篇）

- 使用文档解析能力读取 **25 页答辩 PPT** 与《功能需求总结》Markdown，提炼出项目本质定位——「面向答辩的演示系统，而非生产系统」，并据此确立"可演示性优先、轻量部署"的技术基调；
- 输出功能效果清单（大屏/AI 读片/患者/设备/移动端等模块的"甲方可见效果"），为后续里程碑拆分提供依据。

### 5.2 里程碑化开发（M0–M8）

按"骨架先行、逐模块交付、每步可验收"的节奏推进，共 9 个里程碑：

| 里程碑 | 内容 | 里程碑 | 内容 |
|--------|------|--------|------|
| M0 | 工程骨架 + 文档体系 | M5 | AI 辅助诊断（3 秒读片动画 + 结构化报告 + 医生复核） |
| M1 | 登录与 RBAC 权限 | M6 | 设备与耗材管理（台账/趋势/状态联动/库存告警/出入库） |
| M2 | 数据中心大屏（5 类可视化） | M7 | 移动端 H5（扫码入口 + 免登录只读报告与趋势） |
| M3 | 患者管理（含结论随日期演化） | M8 | 系统设置（信息/权限矩阵/数据维护/关于） |
| M4 | 检查管理（预约 + 模拟采集 + 闭环） | — | — |

每个里程碑遵循固定工作流：**数据先行 → 后端接口 → 前端页面 → 组件测试 → 构建验证 → 交付验收脚本**。

### 5.3 三份管理文档实时维护

项目全程维护并同步更新三份管理文档，方便甲方随时掌握进度：

- `docs/01-项目整体开发流程.md`：里程碑计划、单模块标准工作流、文档与验收机制；
- `docs/02-项目进度.md`：进度主控表（每完成一项功能实时更新）+ 各期自测记录与缺陷修复记录；
- `docs/03-已放弃的技术路线和原因.md`：**35 条技术决策记录**（D1–D35），逐条说明"放弃什么、为什么、替代方案、影响"。

### 5.4 测试先行的质量保障

- 建立 **vitest + jsdom 组件测试资产**（23 个测试文件 / 183 条用例，`npm run test` 一键回归），覆盖纯函数（数据查询/演化/流转/报告/系统信息）、组件渲染与交互、以及**并发与异常防护**场景；
- 每个里程碑交付前执行"测试全绿 + 构建通过 + 接口实测"三重验证；接口实测统一使用 Node fetch 脚本（UTF-8，与浏览器一致）。

### 5.5 真实缺陷的定位与修复（全过程 5 类）

| 缺陷 | 根因与修复要点 |
|------|----------------|
| 登录后大屏"无限加载" | 定位为前端等待无兜底的组合问题（非重复请求型死循环）：请求超时 + Mock 回退、8 秒 UI 保险丝、路由守卫熔断、全局错误横幅、验收脚本就绪探测 |
| 三个图表模块空白 + 诊断横幅 | jsdom 挂载真实组件复现，抓到 `TypeError: optionGetter is not a function`（把 computed ref 当函数调用），重写 useChart 并改 SVG 渲染器 + 降级提示 |
| 区域热力"颜色无变化" | 实测 DataV geojson 为全称（"湖南省"）而数据为简称（"湖南"），匹配率 0/12 导致 visualMap 从未生效，新增名称规范化映射 |
| AI 读片"报告闪现即消失" | 定位为并发竞态（网络等待期无反馈 → 用户连点 → 后发请求清空先发结果），引入 reading 状态做并发防护与即时反馈 |
| db.json 尾部残留致 JSON 解析失败 | 写入未成功截断（本机环境安全软件文件过滤冲突），所有写入点统一加「truncate → 写 → 回读比对」防御 |

上述缺陷均在修复后补充了**回归测试用例**，避免复发。

### 5.6 工程经验与跨会话记忆沉淀

- 项目记忆中沉淀了技术决策、环境陷阱（中文路径、缓存权限、测试并行度）、协作偏好等，使跨会话开发保持上下文连续；
- 例如：`el-dialog @opened 在 jsdom 不触发 → 用 watch(visible)`；`ECharts 容器函数 ref 在 jsdom 不可靠 → 拆子组件复用 useChart`；`测试日期禁用硬编码与 todayStr() 混用`。

### 5.7 交付自动化

- **7 个双击验收入口**：每个模块一个 `.bat`，内置端口清理、依赖检测、服务启动、就绪探测（就绪后才打开浏览器）、验收步骤清单打印，甲方零学习成本验收；
- **一键安装脚本**：`安装依赖.bat`；
- **离线交付包**：将四目录与验收脚本打包为 `demo/` 快照并内置依赖（约 198 MB），**答辩现场无需联网即可运行**；打包后已在独立环境完成启动验证（后端健康检查、前端页面、接口抽查）。

| 指标 | 数值 |
|------|------|
| 交付里程碑 | 9 个（M0–M8），全部交付并通过甲方验收 |

## 七、快速体验路径（答辩演示建议）

1. 双击 `安装依赖.bat`（首次）→ 双击 `验收-01-登录与大屏.bat` → 用 `admin/123456` 登录，浏览数据中心大屏；
2. 「AI 辅助诊断」→ 选患者（如搜索"王桂英"）→ 点「AI 读片」观看 3 秒四阶段动画 → 查看病灶圈注报告 → 「确认签发」；

6. 「系统设置 → 数据维护」一键复位全部演示数据，准备下一轮演示。
